# Internationalization

## Locales

Five supported locales: `en` (default), `ja`, `fr`, `zh-CN` (Simplified Chinese), `zh-TW` (Traditional Chinese, Taiwan usage)

The Chinese locales keep their canonical codes internally (Sanity `language` values, hreflang, `lang`) but are served under lowercase URL prefixes: `/zh-cn` and `/zh-tw` (see `localeToPrefix` and `prefixToLocale` in `i18n/routing.ts`).

## Translation Files

Location: `messages/{en,ja,fr,zh-CN,zh-TW}.json`

### Naming Convention

- **Namespaces**: PascalCase (e.g., `"ContactForm"`)
- **Keys**: snake_case (e.g., `"submit_button"`)

```json
{
  "ContactForm": {
    "submit_button": "Send message",
    "success_message": "Thank you for contacting us"
  }
}
```

## Usage

Components use `use-intl` hooks; the `$locale` route provides the catalog through `IntlProvider`.

```tsx
import { useTranslations } from 'use-intl'

export function ContactForm() {
  const t = useTranslations('ContactForm')
  return <button>{t('submit_button')}</button>
}
```

Read the active locale with `useLocale()` in components, or from the route's `params.locale`
in loaders and `head()`. It is the BCP 47 code (`zh-CN`); the URL prefix (`/zh-cn`) only
exists in the `$locale` route's `params.parse`/`stringify`.

Outside React (a route's `head()`), build a translator with `getMetadataTranslator` from
`lib/locale-head.ts`.

Catalogs are precompiled at build time by `vite.config.ts`, which also regenerates
`messages/en.d.json.ts` for typed message arguments.

## Key Rules

- All user-facing strings must be in `messages/en.json`
- Never hardcode text in components
- Use ICU message format for plurals and arguments
- Keep all locale files synchronized with `en.json`
